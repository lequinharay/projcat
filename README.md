# projcat (Project Concatenator)

[![Go Test](https://github.com/lequinharay/projcat/actions/workflows/test.yml/badge.svg)](https://github.com/lequinharay/projcat/actions/workflows/test.yml)

## Description

`projcat` （推奨エイリアス: `pcat` ）は、開発プロジェクトのソースコード、ディレクトリ構造、およびメタドキュメント（READMEや仕様書など）を、構造化された1ファイルのMarkdownテキストとして美しく連結・出力するコマンドラインツール（CLI）です。

LLM（Large Language Models）のコンテキストにプロジェクト全体の構造や特定のソースコードを一度にインプットしたい場合や、コードベースの構成を俯瞰してドキュメント化したい場合に非常に便利です。Markdownネスト破壊を回避する動的なエスケープ処理、`.gitignore` に準拠した柔軟な除外判定（非実在パスの安全なガードを含む）、およびOSに依存しないクロスコンパイル（スラッシュ区切りへの統一）に対応した堅牢な設計になっています。

### Output Structure Overview

本ツールが生成するMarkdownは、以下の3つの主要セクションで構成されます。

* Directory Structure: プロジェクト（または指定サブディレクトリ）のツリー構造を視覚的に出力します。
* Meta Documents: README.md や仕様書など、プロジェクトの概要を把握するための重要なドキュメントを最優先で配置します。
* Source Codes: 各ソースコードの内容を、適切なマークダウンのコードブロック（言語ごとのシンタックスハイライト付き）で結合・出力します。

### Special Files and Directories

引数で対象のサブディレクトリを指定したり、特定の拡張子やキーワードでフィルタリング（表示ファイルの制限）を行ったりした場合でも、プロジェクトの全体像を維持するために、以下の要素は常に除外されず変わらず出力されます。

* プロジェクトのルート（または指定位置）にある主要なメタドキュメント（README.md など）
* Directory Structure（ツリー構造）の全体、およびそこに含まれる主要な設定ディレクトリ・ファイル

これにより、一部のソースコードだけに絞ってLLMに入力したい場合でも、プロジェクト全体の文脈やディレクトリ構成が失われることなく、常に正しい前提知識をLLMに提供することが可能です。

### Custom Configuration Files

リポジトリのルートに以下の設定ファイルを配置することで、走査対象をより詳細にカスタマイズできます。

* `.projcatignore:`
.gitignore と類似の記述形式で、projcat の走査対象から明示的に除外したいファイルやディレクトリを指定できます。一時的なキャッシュや自動生成コードなど、LLMへの入力に含めたくないファイルをクリーンに排除するために使用します。
ただしディレクトリを指定する場合は末尾に `/*` を付ける必要があります。それ以外はファイルとして認識されます
* `.projcatpromptfiles:`
ツール実行時に追加のインプットとして強制的に読み込ませたいプロンプト指示ファイルや、特定のメタドキュメントのパスを記述します。フィルタリングによって他のファイルが制限されている状態であっても、このファイルに指定されたパスの内容は優先的に結合・出力されます。

## Getting Started

### Dependencies

* Go 1.20 以上（ローカルでビルドする場合）
* 実行環境に git コマンドがインストールされており、実行パスが通っていること。
* macOS（主な想定環境、zsh推奨）および Windows（バックスラッシュの自動置換に対応）

### Installing

* 本リポジトリをクローンするか、ソースコードをダウンロードします。
* リポジトリのルートディレクトリで以下のコマンドを実行し、バイナリをビルドしてパスの通った場所に配置します。

```bash
go build -o projcat ./cmd/projcat
# 扱いやすくするために pcat などのエイリアスを設定することをお勧めします
```

### Executing program

* 基本的な実行手順（カレントディレクトリのプロジェクトを走査して出力）

```bash
./projcat
```

* 特定のサブディレクトリ以下のみのファイルを走査して結合する場合の実行手順

```bash
./projcat ./internal/app
```

## Help

よくある問題として、Gitリポジトリの外部、または .git ディレクトリが存在しない場所で実行した場合、ツールは適切なエラーメッセージを出力して終了コード非0で異常終了します。必ずGit管理下のディレクトリ（またはそのサブディレクトリ）で実行してください。
